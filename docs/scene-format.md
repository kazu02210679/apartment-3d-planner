# シーン JSON 形式

書き出し形式の `schemaVersion` は `1` です。JSON は整形済みで、同じ正規化済みシーンからは同じバイト列を生成します。読み込み時は v0 を v1 に移行しますが、書き出しは常に v1 です。

## 基本構造

ルートには `schemaVersion`、`metadata`、`room`、`entities`、`connections` が含まれます。エンティティの `id`、接続の `id`、ポート ID、経由点 ID は安定した文字列です。ID を位置や配列順から導出しないでください。

各エンティティは `catalog.itemId`、`catalog.revision`、任意の `catalog.presetId` を持ちます。`overrides` はカタログ既定値からの明示的な上書き、`properties` は品目固有の検証済みデータ、`extensions` は将来互換の拡張データです。ローカル変換、寸法、親 ID、表示状態、ポートもエンティティに記録します。変換の位置と寸法は mm、回転は度です。親子関係は `parentId` で表し、親の回転・位置は子のローカル座標へ適用されます。

## カタログ、ポート、接続

カタログ定義は既定寸法、許容範囲、プリセット、ローカル mm のポート位置・方向を提供します。インスタンスはそのポートを引き継ぎます。接続の正規形はちょうど 2 端点で、ケーブル端 `end-a` または `end-b` ひとつと、非ケーブル機器ポートひとつです。

既存 v1 データにある複数端点ネットワークは読み込みの互換性のために保持されます。このようなレガシー接続は読み取り専用の経路表示となり、新しい接続作成時にはそのケーブル端を占有済みとして扱います。ケーブル同士、同一ケーブル内、または自己接続の組み合わせは無効です。

`cable.generic` の配線はケーブルエンティティの `properties.routing` にだけ保存します。経由点は順序付きで、ID と局所 mm 座標を持ち、数と座標は検証された上限内に収まります。非ケーブルに予約済みの `routing` プロパティを置くことはできません。

## 読み込みの安全性

読み込みはスキーマ、参照、寸法、ポート、配線、部屋境界を検証します。不正な参照、重複 ID、未知の必須データ、上限外の値は拒否され、既存のシーンと保存済みデータは変更されません。文字列は表示時にテキストとして扱い、HTML として挿入しません。
